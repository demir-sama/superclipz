# SuperClipz ✂️

**Clip the moment. Share it everywhere.** A creator-focused clipper: paste a link or upload media, trim on a timeline, pick 9:16 / 1:1 / 16:9, caption it (AI suggestions incl. a Web3/Crypto tone), export and share to X, Telegram and Discord.

Stack: React + Vite + Tailwind + react-router · Vercel serverless API routes · Node/Express + FFmpeg clipper service · ffmpeg.wasm fallback · Supabase (auth, Postgres, storage).

## Architecture: why the split?

| Piece | Where | What |
|---|---|---|
| Frontend (`/src`) | Vercel | The app. Works with zero keys (demo mode, localStorage). |
| Light API (`/api`) | Vercel serverless | `transcribe` (Whisper-compatible), `captions` (chat model), `discord` (webhook relay), `health`. Fall back to mock transcript / template captions with no key. |
| FFmpeg clipper (`/server`) | Docker on Render / Railway / Fly | `POST /clip` cuts + crops + watermarks with native FFmpeg; resolves YouTube/Twitch via yt-dlp. |
| ffmpeg.wasm | The user's browser | Fallback cutter when `VITE_API_URL` isn't set or the server fails. |

Vercel functions have short timeouts, small request bodies (~4.5 MB) and no FFmpeg binary, so real video cutting can't run there. The frontend calls the clipper at `VITE_API_URL`; if it's missing or down, it cuts in-browser with ffmpeg.wasm (slower, single-threaded, and remote URLs must allow CORS — uploads always work).

## Local setup

```bash
npm install
cp .env.example .env.local   # all optional
npm run dev                  # http://localhost:5173
npm run build && npm run preview
```
API routes run locally with `npx vercel dev`.

### Clipper server
```bash
cd server && npm install && npm start            # needs ffmpeg (+ yt-dlp for YouTube/Twitch) on PATH
# or
docker build -t superclipz-api server && docker run -p 8080:8080 -e ALLOWED_ORIGINS=http://localhost:5173 superclipz-api
```
Deploy: **Render** (`render.yaml` blueprint, Docker, root `server`), **Railway** (root dir `server`, Dockerfile auto-detected) or **Fly** (`cd server && fly launch --copy-config`). Then set `VITE_API_URL` in Vercel to its URL and `ALLOWED_ORIGINS` on the server to your Vercel domain.

### Supabase
1. Create a project → run `supabase/migrations/*.sql` in the SQL editor (or `supabase db push`). Creates `clips` table + public `clips` bucket with owner-only RLS.
2. Set `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`.
3. Auth → URL configuration: Site URL = your Vercel URL; Redirect URLs add `https://<your-domain>/**` and `http://localhost:5173/**`.
4. Auth → Providers → Google: paste Google OAuth client ID/secret. In Google Cloud Console, authorized redirect URI = `https://<project-ref>.supabase.co/auth/v1/callback`.

Plans: user plan is read from `user_metadata.plan` (`free` default → watermark locked on). Set `pro`/`team` in Supabase to unlock.
